# 值得学习的地方（三个信息源分析,作为后续开发参考）

> 采集自 baipiao.org/charity/、link.hcnsec.cn、飞书《免费公益站统计合集》,2026-08。

## 1. baipiao.org/charity/（白嫖org,60 站在册）

**最值得抄的机制:**

- **社区投票定生死**:每个站点卡片有「还能用？」投票(正/负票),`data-vote-window=14` 表示 14 天投票窗口,`data-dead-ratio=0.7` 表示负票超 70% 判死 → **站点状态不完全靠站长手动维护,让访客帮你养数据**
- **失效沉底**:被判死的站自动沉到列表底部(`data-status="dead"`),不用删除,保留历史
- **结构化数据 SEO**:整页输出 JSON-LD(`ItemList`/`BreadcrumbList`),每个站有独立详情页(`/charity/kktoken`),搜索引擎收录友好
- **标签体系**:免费api/claude/注册送额度/每日签到……多维度筛选比单纯文字描述高效
- **增长闭环**:页面底部「提交补充渠道」表单 + QQ 群,内容众包

**落地建议**:我们的表格加「还能用？」投票(可先用 Cloudflare Workers/KV 免费实现);给每个站做详情页(静态生成);加标签字段。

## 2. link.hcnsec.cn（幻城导航站,大厂+中转两类）

- **双分类锚点**:大厂官方(智谱/硅基流动/NVIDIA NIM)与普通中转站分开,各自锚点直达 —— 我们全是中转站,若收录大厂可直接抄
- **星级评分+评论数**:每条 1-5 星、带评论数(如 3.8 分/14 评),比单一档位更细 —— 可作为我们「评分」列的升级方向
- **排序切换**:默认/评分高低/评论最多/最新添加 —— 我们已有筛选,加排序成本低
- **实体背书**:页脚 ICP 备案号 + 运营公司 + 前端开源地址,可信度拉满
- **人格化运营**:收录一条名叫「垃圾」的自嘲条目(5.0 分/8 评),社区氛围做法

**落地建议**:评分列支持点击排序;长期看值得给站点加「评论/备注」社区入口(需后端,可先不加)。

## 3. 飞书《免费公益站统计合集》docx

- **三档评价体系(夯/npc/拉完了)+ 档位定义前置**:先讲清楚每档什么意思再列站,读者预期管理做得好 —— 我们的其他3列已移植该档位,长期可在页头加图例说明
- **免责与预期管理**:「本人精力有限,评价大差不差」「绝不骗人头」等声明,建立信任
- **按档位分组的链接矩阵**:同一档的站点排成名称+注册链接格子,扫一眼就知道优先注册哪些
- **细节备注跟随站点**:「seekai据网友反映有点注水」「LivenHub 有检测勿频繁测压」等一句话忠告,信息密度高 —— 这正是我们 other3 列已在做的事
- **一个隐藏洞察**:「拉完了」档里"倍率非常小,极其适合作为付费站使用" —— 提示可以做一列「倍率」字段

## 4. 我们已有的差异化优势(保持)

- **多源评价聚合对比**(其他2/3/4 三列并排,一家之言变三家互证)
- **私列门控**(体验感/吐槽只有自己看得到,敢写真话)
- **New API 运维联动**(模型/响应/渠道状态一键同步,是"活"的导航页)
- **注册+签到双按钮**(书签同主机提取,点完注册直接去签到)

## 5. 后续开发优先级建议

1. 状态自动巡检:用 Playwright 定时跑一遍全部注册链接(已有 check_links.py 雏形),失效自动标灰 —— 对标白嫖org 的沉底机制
2. 投票/反馈:Cloudflare Workers + KV 免费实现「还能用？」
3. 站点详情页:静态生成 `/site/<name>.html`,SEO 友好
4. 变更日志:每次数据更新生成 diff 页(「今天涨了哪些站、掉了哪些站」),这是纯静态站最容易做出的"活"感
